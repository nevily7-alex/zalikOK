# Що потрібно налаштувати/вирішити перед публікацією

Сайт працює локально, але **не готовий до production**, доки не виконано пункти нижче.

## Дані власника (зараз `null` у `content/site-config.json`; публічні контакти приховані)
- [ ] `domain` — реальний домен (потім з'являться canonical, абсолютні OG-адреси, sitemap, `metadataBase`).
- [ ] `telegramUrl` (https://t.me/…) — без нього CTA «Написати в Telegram» замінено на «Залишити заявку».
- [ ] `email`, за потреби `phone`, `workingHours` (показуються на сторінці підтвердження й у футері), `responseTime`.
- [ ] `operatorName`, `operatorRegistration` — оператор сервісу та реквізити.
- [ ] Підтвердити строки зберігання (технічний default: 180 днів після закриття, 24 год для незавершених завантажень).

## Прайс
- [ ] Підтвердити актуальність цін у `content/prices.json` та, за потреби, додати мінімальні строки по видах робіт (зараз їх у прайсі немає, тому не показуються).
- [ ] Узгодити формулювання послуг з `/umovy` (робота готується разом зі студентом).

- [ ] Перевірити `content/tariffs.json` за реальною вартістю робіт виконавців: це стартові значення, а не підтверджений прайс. Припущення, які треба підтвердити: звичайні строки текстових послуг (по знаках), визначення сторінки (A4, 14 шрифт, 1,5 інтервал, без титулу/змісту/додатків), коефіцієнти складності та терміновості.
- [ ] Узгодити розбіжності між «від» у `prices.json` і мінімумом калькулятора (див. звіт у чаті).

## Юридичні тексти
Тексти власника підключено: `content/legal/terms.md` (Умови) і `content/legal/privacy.md` (Політика). Сторінки лишаються під noindex і поза sitemap, доки: (а) не заповнено всі поля `**[...]**` у текстах (виділені жовтим на сторінках) і (б) `legalStatus` у `content/site-config.json` не змінено з `review_required` після юридичного перегляду.
- [ ] ПІБ і адреса Виконавця (Умови п.1, Політика п.1).
- [ ] Спосіб оплати й дані отримувача (Умови п.4); строк здійснення повернення (Умови п.8).
- [ ] Політика: склад технічних даних і журналів (п.2), технічні постачальники та платіжний сервіс (п.5), розміщення інфраструктури (п.6), цикл видалення резервних копій/журналів (п.7), перелік cookies (п.9).
- [ ] Юридичний перегляд і зміна `legalStatus`.
- [ ] Перевірити назву «ЗалікОк», домен і товарний знак.

## Інфраструктура
- [ ] PostgreSQL (UTF8) + `DATABASE_URL`; `npm run db:migrate`; бекапи.
- [x] Supabase Storage (bucket `zalikok-requests`) перевірено наживо: підписаний PUT, захист розміру, читання, видалення. [ ] Перед запуском: перевірити з реальним доменом; Supabase S3 віддає `Access-Control-Allow-Origin: *` для підписаних URL — це прийнятно, бо кожен URL підписаний, короткоживучий і прив'язаний до розміру/типу.
- [x] RLS на всіх таблицях Supabase (`npm run db:check-rls`). [ ] Запускати після кожної міграції.
- [x] TLS до БД із перевіркою сертифіката (`DATABASE_SSL=verify`, вбудований Supabase Root CA до 2031-04-26; відбиток SHA-256 80:70:25:AD… звірити з Dashboard → Database → SSL).
- [ ] Тариф Supabase: на Free немає point-in-time recovery і проєкт може призупинятися; регіон eu-west-2 (Лондон) — підтвердити для персональних даних.
- [ ] `AUTH_SECRET`, `APP_URL`, HTTPS; створити менеджерів (`admin:create`).
- [ ] Антивірус: `UPLOAD_SCAN_MODE=clamav` + clamd. Без нього вкладення лишаються `pending`, а менеджер не може їх завантажити (захисне значення за замовчуванням).
- [ ] `TRUSTED_PROXY_HEADER` для відомого проксі хостингу (інакше всі відвідувачі ділять один rate-limit кошик). Перевірити, що проксі перезаписує цей заголовок.
- [ ] Спільне сховище rate limit — зараз PostgreSQL (підходить для кількох інстансів).
- [ ] Telegram-сповіщення: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_MANAGER_CHAT_ID`, `NOTIFICATIONS_ENABLED=true`; перевірити лише на власному тестовому отримувачі (production-адаптер локально не запускався; логіка перевірена юніт-тестами з підміненим fetch).
- [ ] Розклад: налаштувати виклик `/api/cron/outbox` (кожні кілька хвилин) та `/api/cron/cleanup` (щодоби) із `CRON_SECRET`, або `npm run outbox:run` / `npm run cleanup`.
- [x] Ліміт спроб входу better-auth зберігається в PostgreSQL (таблиця AuthRateLimit).
- [ ] Аналітика вимкнена; увімкнення потребує політики/згоди відповідно до реального сервісу.

## Відомі обмеження
- Старий формат `.doc` не приймається (немає перевірки OLE/AV); UI та сервер синхронізовано: PDF, DOCX, PNG, JPG.
- PDF із `/JavaScript`, `/Launch`, `/EmbeddedFile` відхиляються (евристика; можливі хибні спрацювання).
- Немає особистого кабінету, онлайн-оплати, відстеження статусу клієнтом — це наступні черги за планом пакета.
- Lighthouse і тести — лабораторні орієнтири, не гарантія польових LCP/CLS/INP.
