# Розгортання на Vercel (тестовий стенд, тариф Hobby)

> Hobby-план Vercel призначений для некомерційного використання: підходить для перевірки до запуску. Перед публічним запуском потрібен тариф **Pro**.
> Поки домен не задано в `content/site-config.json`, сайт закритий від індексації (`robots.txt` забороняє все, на сторінках `noindex`).

## 1. Підготувати змінні (на вашому комп'ютері)

```bash
npm run vercel:env
```

Скрипт читає локальний `.env`, генерує **нові** `AUTH_SECRET` і `CRON_SECRET` для production і створює файл `.vercel-env.txt` з усім необхідним (значення на екран не виводяться). Якщо чогось бракує, він скаже, що саме заповнити (`npm run setup:supabase`, `npm run setup:telegram`).

## 2. Імпортувати проєкт

1. Vercel → **Add New → Project → Import Git Repository** → `nevily7-alex/zalikOK` (якщо репозиторій не видно: **Adjust GitHub App Permissions** і додайте його).
2. Framework: Next.js (визначається сам). Root Directory, Build і Install Command — за замовчуванням.
3. **Environment Variables**: натисніть **Import .env** (або вставте вміст `.vercel-env.txt` у перше поле). Оберіть середовище **лише Production**: так preview-деплої не отримають доступ до робочої бази.
4. **Deploy**. Після успішного імпорту файл `.vercel-env.txt` **видаліть**.

`APP_URL` задавати не потрібно: поки домену немає, адреса береться з Vercel автоматично. Регіон функцій — Лондон (`lhr1`, поруч із базою Supabase) задано в `vercel.json`.

## 3. Перевірити

- Відкрийте адресу `*.vercel.app` з панелі Vercel. Надішліть тестову заявку (з файлом) — вона має з'явитися в `/admin` (вхід: ваш менеджер із Supabase) і в Telegram.
- У картці заявки файл буде «не перевірено»: кнопка **Завантажити (не перевірено)** працює лише з явним підтвердженням, а завантаження записується в журнал.
- Vercel → **Settings → Cron Jobs**: мають бути `/api/cron/outbox` і `/api/cron/cleanup`.

## 4. Розклад на Hobby

Hobby дозволяє cron лише **раз на добу** (інакше деплой не пройде). Тому повтор сповіщень зараз щодобовий. Новинки заявки все одно відправляються одразу, а збої можна повторити кнопкою «Повторити» в картці заявки. Після переходу на Pro змініть у `vercel.json` розклад `outbox` на `*/5 * * * *`.

## 5. Оновлення та міграції

- Кожен `git push` у `main` автоматично розгортається.
- Міграції БД Vercel не запускає: перед пушем зі змінами схеми виконайте локально `npm run db:migrate` (цілиться в Supabase через `DIRECT_URL`) і `npm run db:check-rls`.

## 6. Коли з'явиться домен

1. Vercel → Settings → Domains → додати домен, прописати DNS, як підкаже Vercel.
2. У Vercel додати `APP_URL=https://ваш-домен`.
3. У `content/site-config.json` вказати `domain` (тоді з'являться canonical, sitemap, OG і зникне `noindex`) і зробити коміт.
4. Заповнити юридичні тексти (див. `LAUNCH_BLOCKERS.md`) і перейти на Vercel Pro.

## Обмеження Vercel для нашого сайту

- Автоматичної антивірусної перевірки вкладень немає (ClamAV на Vercel не запустити), тому `UPLOAD_SCAN_MODE=off`. Менеджер завантажує файли з підтвердженням і перевіряє їх антивірусом на своєму комп'ютері. Для автоматичної перевірки знадобиться VPS або зовнішній сервіс.
- Preview-деплої (гілки, pull request) не мають робочих змінних і не повинні використовуватися для перевірки форми.
